STUDY HUB — STANDALONE SAAS DASHBOARD
Bolt AI build brief and application architecture
================================================

GOAL
----
Build a standalone, polished SaaS-style operations dashboard for STUDY HUB, a Ugandan online learning and academic resources platform.

I will download this dashboard project and connect it to the existing Study Hub website/backend later. Build the dashboard as a separate app. Do not edit, replace, or depend on files in the existing Study Hub repository. Do not require live credentials or a backend to run the first version.

The first deliverable is a complete, navigable frontend prototype with realistic, clearly labelled demo data. Organize the code so I can connect real APIs and authentication later without rebuilding the UI. Do not pretend demo actions changed production data.

PRODUCT BOUNDARIES
------------------
- This is an internal Study Hub operations dashboard for the platform owner and staff, not a student-facing learning app and not a multi-school SaaS.
- Do not build subscriptions, billing plans, a school tenant system, or a new student learning portal.
- Keep the existing learner account/profile and public site separate; the dashboard can link to them.
- Document payments remain UGX 1,000 per document with manual Mobile Money verification against the sender phone number. Do not invent automatic payment gateway processing.
- Build the frontend now. Keep data/API/auth integration points clean and documented for later connection.
- Use an obvious "DEMO DATA" indicator throughout the prototype. Seed realistic Uganda-focused examples, but never imply example payments, users, downloads, or analytics are real.

APPLICATION STACK
-----------------
Build a standalone app using:
- Vite
- React
- TypeScript
- Tailwind CSS
- React Router for page navigation
- Lucide React for icons
- Recharts for charts

Use the simplest maintainable structure. Avoid unnecessary state libraries, a database, Supabase, or server implementation in this first downloadable prototype. Keep demo data local and isolated behind typed data services.

PAGES AND MVP FEATURES
----------------------

1. OVERVIEW
- KPI cards: learners, new registrations, library resources, pending contributions, pending payments, completed downloads.
- Clearly label every metric "Demo" and include an illustrative date range.
- Line/bar charts for signups, payment-request status, resource engagement, and downloads.
- Recent activity feed and compact queues for pending payment requests and contributions.
- Quick links to common operations.
- Do not call a pending UGX 1,000 request revenue. Label it "requested amount" unless it is truly verified.

2. PAYMENTS
- Searchable/filterable table: request ID, learner, resource, sender phone, UGX amount, requested date, status, verifier.
- Filters for status/date; sort and paginate the demo collection.
- Clicking a row opens a detail drawer with learner/contact summary, resource summary, request details, and state history.
- Provide demo-only Verify and Reject actions. Require confirmation; Reject requires a reason.
- Show a clear "Demo action — no real payment was verified or rejected" message. Do not send email or affect real downloads.
- Represent pending, verified, downloading, downloaded, and rejected states.

3. RESOURCES
- Search/filter demo resources by title, subject, class, type, format, and source.
- Table/cards show first-page thumbnail-style preview, title, subject, class/level, type, file format, size, source, and status.
- Use local illustrative thumbnail components/placeholders in the prototype; do not fetch protected files or imply a real resource has loaded.
- Resource detail drawer with metadata, demo engagement totals, and "Open resource" link placeholder.
- Previewing is not downloading and never initiates payment.

4. CONTRIBUTIONS
- Demo queue showing submitted files/batches, contributor, date, filename, subject, level, size, and review status.
- Detail/review panel with a local preview placeholder and review checklist.
- Demo-only Approve/Reject actions; rejection requires reason and displays an explicit demo notice.
- Do not claim to move or publish files.

5. LEARNERS
- Searchable/filterable demo learner table: display name, email, class, join date, status, and aggregate activity.
- Profile drawer shows learning preferences, document request summaries, saved-resource count, and account status.
- Use synthetic contact data only; do not expose real users or sensitive credentials.
- Support actions (suspend/restore) are demo-only, confirmed, and visibly labelled as such.

6. MODERATION
- Demo queue for anonymous community suggestions: suggestion text, submitted time, status.
- Approve/Reject controls require confirmation and show a demo-only notice.
- Do not infer or invent identity for anonymous submissions.

7. ANALYTICS
- Date range selector and summary charts for learner registrations, document request statuses, resource engagement, and completed downloads.
- Include brief metric definitions, timestamp/timezone, and demo badge.
- CSV export may export only the clearly labelled demo dataset.
- Do not show MRR, ARR, subscription churn, or automatic payment-gateway revenue.

8. STAFF & ROLES

- Show permission differences in a readable table.
- Any role edit is a local demo interaction only; do not imply real access changed.
- Super Admin has all demo screens. Verifier focuses on payments. Moderator focuses on contributions/suggestions. Support is read-only.
- Add a small reusable permission helper so navigation and buttons can be tested against the selected demo role. This is UI simulation only, not real security.

9. SETTINGS

- Mark settings as sample values/not connected. Do not save settings to production.

10. AUDIT LOG

AI STUDY PRODUCT EXPERIENCE (ADVANCED STUDENT-FACING ONBOARDING)
----------------------------------------------------------------
Build a second major product surface inside the ecosystem: the personalized AI Study experience for students. This is not a small widget; it is a guided, onboarding-driven learning workspace.

A. STUDENT ONBOARDING FLOW
- When a signed-in user opens AI Study, the app first asks: "Are you a student or non-student?"
- If the user is not a student, they land in a general guided dashboard tour and explanatory overview, without academic customisation.
- If the user is a student, ask them to choose their learning level:
  - University
  - Secondary
  - Primary
  - Nursery
- If University:
  - ask year of study
  - ask course/field of study
  - ask preferred learning style or academic focus
  - store these values in the user's profile for AI delivery instructions and contextual prompts
- If Secondary:
  - ask O-Level or A-Level
  - ask class (e.g. S.1, S.2, S.3, S.4, S.5, S.6)
  - ask subjects of focus
  - if they have national exams, include examination board and target exam context when available
- If Primary or Nursery:
  - ask class level and a few dominant learning paths or subjects
- Store the onboarding answers in a persistent learner profile and use them to personalise AI responses, suggestions, and study tasks.

B. GUIDED TOUR / FIRST-LAUNCH EXPERIENCE
- On first login, the student is taken through a compulsory guided onboarding tour that introduces each AI Study section.
- The tour script should explain:
  - the chat tutor
  - saved and liked resources
  - library integrations
  - mastery checklist
  - daily quiz/streaks
  - flashcards and spaced repetition
  - smart study planner
  - documents and search memory pipeline
  - how the AI uses learner context to personalise responses
- The tour should be skippable only after a clear confirmation; a full guided run should be default for new students.
- The onboarding should not feel like a generic chat app. It should feel like a study coach setup wizard.

C. AI MEMORY, SEARCH CONTEXT, AND LIBRARY INTEGRATION
- The AI should remember the user's study profile and prior searches in a personal context layer.
- Maintain a short-term and long-term memory model for:
  - selected level/class/subjects
  - recent searches
  - saved documents
  - liked resources
  - reviewed topics and mastery progress
  - repeated misconceptions or weak topics
- The AI should be able to query the Study Hub library or a student's saved/liked content when it needs evidence.
- Include a document pipeline where the AI can use a retrieval/skill workflow to read resource contents when needed, rather than answering from generic knowledge alone.
- Support a "Use my saved resources" toggle and "Use library context" toggle.
- The AI study screen should include quick access to:
  - saved documents
  - liked resources
  - recent searches
  - relevant library documents by subject
  - study notes and syllabus links

D. PERSONALIZED STUDY DASHBOARD
- After onboarding, the student lands on a dashboard with these major panels:
  - AI Tutor chat panel
  - My learning profile and study context
  - Saved resources and liked documents
  - Daily study streak + question of the day
  - Syllabus mastery progress
  - Recommended next actions
  - Smart study planner and quick tasks
  - Flashcards and revision deck
  - Resource search and quick library access
- The dashboard should feel like a study operating system, not a simple chatbot page.
- The AI runs in the background to set up study topics tailored to the learner's class and selected subjects.

E. MASTERY CHECKLIST / SYLLABUS TRACKER
- Add a dedicated page or section called: "UNEB / A-Level Syllabus Mastery Checklist" or equivalent based on the learner's level.
- Students should see their syllabus broken down topic-by-topic with checkboxes or status pills.
- Example structure:
  - Subject
  - Topic unit
  - Status: Mastered / Needs Revision / Not Started
  - Confidence rating
  - Linked notes or resource references
- Each completion or update should contribute to a visible progress bar and total percentage.
- Example output: "74% Syllabus Complete"
- Students should be able to mark topics as mastered or revise later.
- This feature is a powerful retention loop because learners return daily to watch the bar grow.

F. AI HANDWRITTEN ANSWER & MATH PROOF GRADER
- Include an image upload feature for handwritten work or diagrams.
- Students can upload photos of:
  - handwritten equations
  - chemistry working or structures
  - biology diagrams or labelled drawings
  - math proof steps or algebra
- The AI should evaluate the response with an exam-style rubric and provide:
  - marks out of 10 or out of a configured rubric
  - step-by-step feedback
  - exact mistake highlighting where relevant
  - suggestions for improvement
- This should behave like a strict UNEB examiner rather than a generic tutor.
- This feature should live in a dedicated "Answer Grader" or "AI Marking" workspace.

G. DAILY QUESTION OF THE DAY + STREAKS
- Daily question card shown on the homepage or main dashboard.
- Each day includes:
  - one multiple-choice or short-answer question
  - a countdown to exam season or next exam milestone
  - study streak counter
- Correct answer extends the streak; missed days reset it.
- Show a simple motivational UI: "🔥 3-Day Streak" and progress cues.
- The content should be generated from subject context and learner profile.
- Keep this feature under a clear and non-harmful daily reward loop, not excessive gamification.

H. FLASHCARDS AND SPACED REPETITION
- Build a flashcards feature with:
  - term/definition cards
  - formula cards
  - biological concept cards
  - chemistry equation cards
  - physics law cards
- Use spaced repetition logic to re-show weak cards more often.
- Include quick review mode for mobile or commuter use.
- Allow cards to be generated from uploaded or saved resources, existing library notes, or AI-generated study notes.

I. SMART STUDY PLANNER
- Add a Smart Study Planner page that asks for:
  - exam date
  - weakest subjects
  - available study hours per week
  - current study habits
- Then generate a custom revision timetable by day and week.
- Example task generation:
  - "Today's Goal: Read Photosynthesis notes and complete 3 questions"
  - "Revise Genetics and complete 5 flashcards"
- Use the student's profile and school level to create realistic study plans.
- Keep tasks actionable and short-term.

J. AI TUTOR UX DESIGN
- AI tutor panel should feel like a structured coach, not just a chat box.
- Include:
  - chat panel
  - suggested questions
  - exam mode toggle
  - answer mode toggle
  - context chips (subject, class, current topic)
  - saved-resource references
  - recent search history
  - summary of outstanding topics
- The AI should be able to answer in a way that reflects the chosen learner profile and subject list.

K. ACCESS TO LIBRARY RESOURCES AND USER CONTENT
- Students should be able to access library resources from the AI Study dashboard.
- They should also see:
  - the documents they saved
  - the documents they liked
  - recent library resource suggestions
  - document previews connected to relevant learning topics
- Include a "Use this resource for context" action that lets the AI read and summarise the document for study help.
- This should be a clear, privacy-aware workflow: only the learner's own saved resources or approved public library materials should be used.
